## 一、什么是向量数据库

**向量数据库（Vector Database）** 是一类专门用于存储、索引和检索**高维向量**的数据库系统。它与传统数据库的根本区别在于查询方式：

| 对比维度 | 传统数据库（MySQL 等） | 向量数据库 |
|---------|----------------------|-----------|
| 存储内容 | 结构化标量（数字、字符串） | 高维浮点向量（如 768、1536 维）+ 元数据 |
| 查询方式 | 精确匹配（`WHERE id = 1`）、范围查询 | **相似度查询**（"找出与这个向量最接近的 K 条"） |
| 查询结果 | 要么匹配、要么不匹配 | 按相似度排序的 Top-K 列表 |
| 索引技术 | B+ 树、哈希索引、LSM-Tree | ANN 索引（HNSW、IVF、PQ 等） |
| 典型场景 | 事务处理（OLTP）、报表（OLAP） | 语义搜索、RAG、推荐、以图搜图 |

一个完整的向量数据库通常提供：

- **向量存储**：持久化保存向量及关联的原始数据/元数据；
- **向量索引**：为快速相似度检索建立的特殊数据结构；
- **CRUD 与元数据过滤**：支持增删改查，以及"在满足某条件的子集内做相似度搜索"（混合查询）；
- **分布式与高可用**：分片（Sharding）、副本（Replica）、水平扩展。

值得注意的是，向量数据库本身**不做 Embedding**——把原始数据变成向量是上游 Embedding 模型（通常是深度神经网络）的工作，向量数据库负责的是"向量化之后"的存储与检索。但也正因为如此，理解"向量从哪里来"是理解向量数据库的前提，这就是下文的核心内容。

## 二、核心思想：语义即几何

向量数据库有效的前提是一个深刻的假设：

> **语义上相似的东西，经过神经网络编码后，在高维空间中的距离也相近。**

深度神经网络把一段话、一张图、一段音频压缩成一个固定长度的浮点数组，例如：

```
"今天天气真好"    →  [0.12, -0.45, 0.78, ..., 0.33]   （768 个数字）
"今日晴空万里"    →  [0.11, -0.44, 0.80, ..., 0.31]   （与上句距离很近）
"股票涨停了"      →  [-0.65, 0.21, -0.10, ..., 0.9]   （与上两句距离很远）
```

这个过程叫 **Embedding（嵌入）**：把离散、异构的原始数据"嵌入"到一个连续的欧氏空间中。神经网络的训练目标正是"让相似的东西靠近、不相似的东西远离"，因此向量之间的**几何关系**（距离、夹角）就承载了**语义关系**。

一旦万物皆可表示为同一空间中的向量，"搜索"就从"字符串匹配"升级为"几何最近邻查找"——这就是现代语义检索的全部秘密。

一个 Embedding 通常具有以下性质：

- **定长**：同一模型输出的向量维度固定（如 BERT 输出 768 维，OpenAI `text-embedding-3-large` 输出 3072 维）；
- **稠密**：几乎每个分量都是非零小数（区别于 One-hot 的稀疏表示）；
- **语义可运算**：经典例子 `king − man + woman ≈ queen`（词向量）；图片向量之间的方向可能对应"性别""年龄"等属性；
- **模态可对齐**：像 CLIP 这样的模型能把文字和图片映射到**同一个空间**，使"用一句话搜图"成为可能。

## 三、各模态数据如何被转换为向量

不同模态使用不同的神经网络"编码器"（Encoder），但整体范式一致：

```
原始数据 ──► 预处理 ──► 神经网络编码器 ──► 特征汇聚（Pooling）──► 定长向量 ──► L2 归一化 ──► 存入向量数据库
```

### 3.1 文本 → 向量

文本是最经典的嵌入对象，其技术经历了三代演进。

#### （1）第一代：词袋与 One-hot（非语义）

- **One-hot 编码**：词表大小为 V，每个词表示为 V 维向量，只有对应位置为 1。问题：维度等于词表大小（几万到几十万）、**完全无法表达语义**（"猫"和"狗"的正交距离与"猫"和"飞机"一样远）。
- **TF-IDF / BM25**：统计词频的稀疏加权表示，仍是"字面匹配"，不理解同义词。

#### （2）第二代：Word2Vec / GloVe——静态词向量（2013）

**Word2Vec（Mikolov et al., 2013）** 首次让词向量携带语义。它基于一个语言学假设（分布式假说）：**上下文相似的词，语义相似**。

两种网络结构，本质都是一个极浅的神经网络：

- **CBOW（Continuous Bag of Words）**：用上下文词预测中心词。
  - 输入：中心词前后各 c 个词的 One-hot → 查表得到词向量 → 求平均 → 经过一个 `V×d` 的投影矩阵 → softmax 预测中心词。
  - 训练收敛后，**那个投影矩阵的每一列就是每个词的 d 维向量**（典型 d=100~300）。
- **Skip-gram**：反过来，用中心词预测上下文，对低频词效果更好。

```
     "我 爱 机器 学习"          Skip-gram 示意
     上下文窗口 [爱, 机器]
          │
          ▼
   One-hot × 2 ──► 查嵌入矩阵 W_in ──► 平均/拼接 ──► W_out ──► softmax("学习")
                                                                    │
        训练目标：最大化真实上下文词的概率（负采样 Negative Sampling 代替全词表 softmax）
```

**负采样**是关键优化：不做全词表的 softmax（代价太大），而是从词表中随机抽 K 个"负例词"，训练模型区分"真上下文"和"负例噪声词"。高频词（"的""了"）按频率降权采样。

局限：**一个词只有一个向量**，无法处理一词多义（"苹果"在"吃苹果"和"苹果手机"中向量相同），也天然无法表示句子和篇章。

#### （3）第三代：Transformer / BERT——上下文相关向量（2018 至今）

现代文本嵌入的主流方案是 **Transformer 编码器**（BERT 及其后继者）：

**第一步：Tokenization（分词）**
文本被切分为子词单元（Token），常用算法为 **BPE（Byte Pair Encoding）/ WordPiece**：从字符开始，迭代合并语料中最高频的相邻字节对，最终得到约 3 万~10 万规模的子词表，既能覆盖任意新词，又控制词表规模。每个 Token 映射为一个整数 ID。

**第二步：嵌入层**
`Token ID → 词嵌入向量`，再加上**位置编码**（正弦函数或可学习向量），因为自注意力本身不感知顺序。输入序列形如 `[CLS] 我 爱 机器 学习 [SEP]`。

**第三步：多层自注意力（Self-Attention）**
这是核心算法。每个 Token 的向量通过三个投影矩阵生成 Query、Key、Value 三个角色：

```
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
```

- 每个词用它的 Q 与所有词的 K 做点积 → 得到"我应该关注谁"的注意力权重 → 按权重加权求和所有词的 V。
- 效果：**"苹果"在"吃苹果"中会大量吸收"吃"的信息，在"苹果发布会"中会吸收"发布会"的信息**——多义性问题由此解决。
- 多头注意力（Multi-Head）：并行的 h 组注意力各自关注不同模式（语法、指代、语义……），结果拼接。BERT-base 堆叠 12 层、12 头、隐藏维度 768。

**第四步：池化（Pooling）—— 从 Token 序列到单个向量**
Transformer 输出的是"每个 Token 一个向量"（如 10 个词 → 10×768），而入库需要**一个**向量，常见做法：

- **CLS 池化**：取特殊标记 `[CLS]` 的最终输出，它在预训练中被训练为"全文摘要"；
- **均值池化（Mean Pooling）**：对所有 Token 向量取平均，实践中通常更稳健，是 Sentence-BERT 系列的默认选择；
- 最后一般做 **L2 归一化**，使所有向量落在单位球面上，方便用内积/余弦度量。

**第五步：面向检索的微调（对比学习）**
原始 BERT 不直接适合检索，现代嵌入模型（Sentence-BERT、OpenAI text-embedding、BGE、GTE、Jina 等）用**对比学习（Contrastive Learning）**微调：

- **损失函数 InfoNCE**：

```
L = −log( exp(sim(q, d⁺)/τ) / Σᵢ exp(sim(q, dᵢ)/τ) )
```

  其中 `d⁺` 是正例（与问题相关的文档），`dᵢ` 包含批内其他负例；τ 是温度系数。直觉是"在众多候选中把正确答案的相似度拉到最高"——这恰好模拟了检索行为。
- **正例来源**：人工标注问答对、弱监督（标题-正文）、**难负例挖掘**（随机负例太简单，用 BM25 捞出的"看起来像但不相关"的文档做负例，效果显著提升）；
- **SimCSE**：把同一句话两次过模型（Dropout 不同）互为正例，无监督学习句子表示。

**小结**：文本嵌入 = `Transformer(分词后的文本) → 池化 → 归一化`，输出 384~3072 维的稠密向量。

### 3.2 图片 → 向量

#### （1）CNN 时代：卷积特征提取（2012–2020）

**卷积神经网络（CNN）** 模拟"视觉皮层由局部到全局"的层次化感知：

```
原始图像 224×224×3 (RGB)
   │  卷积核 3×3 滑动扫描，提取边缘/颜色/纹理等局部模式
   ▼
Conv 层 × N  （分辨率逐层减半，通道数逐层翻倍：低级特征 → 高级语义）
   │  例：卷积层1认出"毛发和圆弧"，卷积层10认出"猫耳朵"，卷积层13认出"这是一只猫"
   ▼
全局平均池化 / 展平
   ▼
2048 维特征向量（ResNet-50 的倒数第二层输出）
```

- **卷积**：一个小矩阵（如 3×3）在图像上滑动做点积，同一组权重扫过全图 → 天然具有平移不变性，且参数量远小于全连接；
- **池化**：2×2 最大/平均池化把图缩小一半，扩大感受野、增强鲁棒性；
- **残差连接（ResNet, 2015）**：`输出 = F(x) + x`，让上百层网络也能稳定训练，ResNet-50 至今仍是最常用的图像嵌入 backbone 之一；
- **以图搜图的做法**：去掉分类头，取**倒数第二层的全局特征**（如 ResNet 的 2048 维）作为图像向量——它比分类输出更泛化，保留了"类内相似性"。

#### （2）ViT 时代：把图像当句子处理（2020 至今）

**Vision Transformer（ViT）** 的思路出人意料地简单：

1. 把图像切成 **16×16 像素的小块（Patch）**，一张 224×224 图 = 196 个 patch；
2. 每个 patch 展平后线性投影成一个 token 向量（相当于"图像的词"）；
3. 加位置编码，前面拼一个 `[CLS]` token；
4. 整个序列送入标准 Transformer 编码器；
5. 取 `[CLS]` 输出作为图像向量（典型 768/1024 维）。

ViT 在大规模数据上超越了 CNN，且已成为多模态模型（CLIP、GPT-4V 类）的标配视觉编码器。

#### （3）训练范式：从"分类监督"到"对比学习"

- **ImageNet 分类训练**：模型为 1000 类分类而训练，特征"免费"可用于检索，但语义受限于分类标签；
- **自监督对比学习（SimCLR、MoCo, 2020）**：同一张图做两次随机增强（裁剪、变色、模糊）作为正例对，批次内其他图为负例，用 InfoNCE 训练——不需要任何标注，百万、千万级图片均可训练；
- **CLIP（OpenAI, 2021）——跨模态对齐的里程碑**：
  - 在 **4 亿网络图文对**上训练双塔模型：图像编码器（ViT）+ 文本编码器（Transformer）；
  - 损失函数是**对称的 InfoNCE 矩阵损失**：N 个图文对构成 N×N 相似度矩阵，对角线（正确配对）拉高，其余推低，行、列两个方向各算一次交叉熵；
  - 效果：**图像向量和文本向量落在同一空间**，"夕阳下的海滩"这句话的向量，天然靠近相应照片的向量——以文搜图、零样本分类都由此实现。

**小结**：图片嵌入 = `CNN 或 ViT(预处理后的像素) → 池化/CLS → 归一化`，输出 512~1536 维向量；若需跨模态检索，选用 CLIP 类模型。

### 3.3 视频 → 向量

视频是"图像序列 + 音频 + 可能的字幕"，向量化需要同时处理**空间**（每帧画面）和**时间**（帧间运动）两个维度。

#### （1）通用流水线：帧特征 + 时序聚合（最常用）

```
视频 ──► 抽帧（每秒1~5帧或关键帧检测）──► N 帧图像
              │
              ▼  每帧过图像编码器（ResNet / ViT / CLIP）
        N 个帧向量 [v₁, v₂, ..., v_N]
              │
              ▼  时序聚合（Temporal Pooling）
     ┌────────┴────────┐
     │ 平均池化 / 最大池化          │ 简单高效
     │ LSTM / GRU                 │ 建模时序依赖
     │ Transformer 时间注意力      │ 当前主流
     │ NetVLAD                    │ 可学习的"词袋"聚合，保留多中心信息
     └────────┬────────┘
              ▼
        单个视频向量（512~1024 维）
```

平均池化会"抹平"时序信息（一段"人物出现→离开"的视频和其倒放得到几乎相同的向量），因此精细任务需要时序模型。

#### （2）3D CNN：直接学习时空特征

把卷积核从 2D（宽×高）扩展到 3D（宽×高×时间），一次卷积同时看到连续多帧：

- **C3D**：3×3×3 立方体卷积核；
- **I3D**：把成熟的 2D 网络（Inception）"膨胀"为 3D 版本，可继承 ImageNet 预训练权重；
- **SlowFast**：双通路网络——慢通路低帧率看空间细节，快通路高帧率看快速运动，特征融合。

#### （3）视频 Transformer

- **TimeSformer**：将注意力**分解**为"空间注意力（帧内）+ 时间注意力（跨帧）"交替进行，把 O(N²·T²) 的开销降为线性组合；
- **VideoMAE**：对视频做时空块掩码（如遮住 90% 的时空 patch），训练模型重建被遮挡内容——视频版 MAE 自监督预训练；
- **VideoCLIP / X-CLIP**：把 CLIP 的对比学习扩展到"视频-文本"对，实现用自然语言搜视频。

#### （4）工程要点

- **多模态融合**：工业级视频检索常把"画面向量 + 音频向量 + ASR 文本向量 + OCR 文本向量"分别入库（或在特征层拼接），检索时加权融合；
- **粒度选择**：入库粒度可以是"整段视频"（摘要检索）、"镜头/场景"（shot detection 切分后逐段嵌入，支持定位到秒）、或"帧"（精确截图检索），粒度越细索引越大。

**小结**：视频嵌入 = `抽帧 → 图像编码 → 时序建模/聚合`，或端到端 `3D CNN / Video Transformer`。

### 3.4 语音 → 向量

语音向量化有两条主线：**面向内容的**（说了什么，用于语音搜索、ASR 检索）和**面向说话人的**（谁在说，用于声纹识别）。两者共用相似的信号处理前端。

#### （1）信号预处理：从波形到声谱

原始音频是采样点序列（如 16kHz、16bit PCM），1 分钟就有近百万个点。神经网络不直接吃波形（wav2vec 类除外），经典做法是转成**时频特征**：

```
波形 ──► 预加重（补偿高频衰减）
     ──► 分帧：每帧 20~25ms（约 400 采样点），帧移 10ms（语音短时平稳假设）
     ──► 加汉明窗（减少频谱泄漏）
     ──► FFT 快速傅里叶变换 → 得到每帧的频谱
     ──► 通过梅尔滤波器组（模拟人耳对低频敏感、高频不敏感的感知特性）
     ──► 取对数能量
     ├─► Fbank：直接得到 (时间帧 × 80 梅尔频带) 的二维"声谱图" ← 深度模型最爱
     └─► 再做离散余弦变换 DCT → 取前 13 维 + 一二阶差分 = MFCC（39 维） ← 经典特征
```

**梅尔频谱图本质上是语音的"图像"**——横轴时间、纵轴梅尔频率、像素值是能量。因此可以把处理图像的 CNN 直接迁移过来处理语音。

#### （2）面向内容：自监督语音模型

- **wav2vec 2.0（Meta, 2020）**：
  1. **卷积特征编码器**：多层一维卷积直接作用于**原始波形**，输出 512 维、每 20ms 一帧的特征序列；
  2. 对特征序列做**随机掩码**（遮住部分时间段）；
  3. 掩码后的表示送入 **Transformer** 上下文网络；
  4. 训练目标：对比学习——模型要从一组干扰项中**识别出被掩位置的真实量化表示**；
  5. 效果：无标注音频即可预训练，之后微调一个小线性层即可做 ASR，或直接取编码器输出作为语音语义向量。
- **HuBERT**：类似 BERT 的掩码预测，但预测目标是离线聚类得到的"伪音素标签"，训练更稳定；
- **Whisper Encoder（OpenAI, 2022）**：80 维对数梅尔频谱 → 双卷积下采样 → Transformer 编码器，取编码器各帧表示池化后即可作为语音向量，天然携带语义（它训练时见过 680k 小时标注音频）。

#### （3）面向说话人：声纹嵌入（Speaker Embedding）

目标与内容无关，只刻画"这个声音属于谁"，如同声音的指纹：

- **d-vector**：LSTM 对每帧建模，取最后一帧隐状态；
- **x-vector（2018，经典）**：**时延神经网络（TDNN）** 逐层扩大时间上下文 → **统计池化层**（对整段语音的所有帧计算均值和标准差并拼接，把变长序列压成固定长度）→ 全连接层 → 提取**512 维说话人嵌入**，L2 归一化后用余弦相似度比对；
- **ECAPA-TDNN（2020，当前主流）**：引入通道注意力（SE 模块）与多层特征聚合，声纹识别错误率显著下降；
- **训练方式**：交叉熵分类海量说话人 ID（数千~数十万人），或者广义端到端损失（GE2E）——训练"同一人的不同 utterance 在嵌入空间聚在一起"。

#### （4）应用上的区别

| 目标 | 模型 | 向量含义 | 典型用途 |
|------|------|---------|---------|
| 内容语义 | wav2vec 2.0 / Whisper encoder | "说了什么" | 语音搜索、会议纪要检索、播客按语义定位 |
| 说话人身份 | x-vector / ECAPA-TDNN | "谁在说" | 声纹解锁、客服身份核验、会议说话人分离 |
| 声学场景 | VGGish / PANNs | "听起来像什么" | 音乐检索、环境音分类、音频去重 |

**小结**：语音嵌入 = `波形 → 分帧加窗 → 梅尔频谱（或卷积编码器直接处理波形）→ 深度网络 → 统计池化 → 定长向量`。

### （5）各模态对照总表

| 模态 | 预处理 | 主流编码器 | 核心算法 | 池化方式 | 典型维度 |
|------|--------|-----------|---------|---------|---------|
| 文本 | BPE 分词 | BERT / BGE / GTE | 自注意力 + 对比学习 | CLS / Mean | 384~3072 |
| 图片 | 缩放归一化 | ResNet / ViT / CLIP-Image | 卷积 / Patch 注意力 | GAP / CLS | 512~1536 |
| 视频 | 抽帧 | I3D / TimeSformer / CLIP 帧特征 | 3D 卷积 / 时间注意力 | Temporal Pooling | 512~1024 |
| 语音 | 分帧→梅尔频谱 | wav2vec 2.0 / ECAPA-TDNN | 卷积+Transformer / TDNN | 统计池化 | 256~1024 |

## 四、相似度度量算法

向量入库后，检索的本质是**距离计算**。三种主流度量：

**1. 欧氏距离（L2）** —— 空间直线距离，衡量"绝对差异"：

```
d(a, b) = √( Σᵢ (aᵢ − bᵢ)² )        值越小越相似
```

**2. 内积（Inner Product / IP）** —— 衡量"对齐程度"，隐含方向性和模长信息：

```
s(a, b) = Σᵢ aᵢ·bᵢ                  值越大越相似
```

**3. 余弦相似度（Cosine）** —— 只看夹角、不看长度，衡量"方向一致性"：

```
cos(θ) = (a·b) / (‖a‖·‖b‖)          取值 [−1, 1]，越大越相似
```

**三者的关系与选择经验**：

- 如果所有向量都做了 **L2 归一化**（模长为 1），则三者完全等价：`‖a−b‖² = 2 − 2·cos(θ)`。这是工程上的通行做法——归一化后用内积计算（最快），等价于余弦排序；
- **文本/语义检索**几乎总是用余弦（或归一化内积）；
- **推荐系统**常用内积：用户向量和物品向量的模长本身编码了"热度/活跃度"信息，归一化会丢掉；
- 图片特征若来自未归一化的 CNN，常用 L2。

此外，**二值向量**（量化后）用**汉明距离**（不同比特的个数）度量，可用 XOR + popcount 指令极速计算。

## 五、向量数据库核心检索算法（ANN）

### 5.1 为什么需要"近似"：暴力检索的困境

给定查询向量 q，要在 N 条向量中找出 Top-K 最近邻，最朴素的**暴力搜索**需要与库中每条向量算一次距离：

```
时间复杂度 = O(N × d)
```

- N = 1 亿条、d = 768 维，单次查询需数百亿次浮点运算，即使 GPU 也难以满足毫秒级在线服务；
- 更致命的是**维数灾难（Curse of Dimensionality）**：在几百维空间中，任意两点间的距离趋于相近，传统 B+ 树、KD 树等索引急剧退化（KD 树在维度 >20 时基本失效）。

因此向量数据库普遍采用 **ANN（Approximate Nearest Neighbor，近似最近邻）** 算法：**牺牲一点点召回率（比如 95%~99%），换取成百上千倍的速度提升**。召回率与速度的权衡是所有 ANN 算法的设计主轴。

### 5.2 Flat：暴力精确检索

最简单的索引——不做任何索引，逐条精确计算。中小规模（百万级以下）+ 高性能硬件（GPU/SIMD 优化）下其实是可行选项，且**召回率 100%**，常被用作其他算法召回率评估的基准（ground truth）。很多向量数据库在小分片（segment）内部就采用 Flat。

### 5.3 IVF：倒排文件索引（聚类分桶）

**IVF（Inverted File Index）** 的思想："先分桶，再在最近的几个桶里找"。

**建索引**：用 **k-means 聚类**把全部向量分成 `nlist` 个簇（如 4096 个），记录每个簇的质心，每个向量归属最近的簇——相当于把向量空间划分成 Voronoi 单元，建立"质心 → 簇内向量列表"的倒排表。

**查询**：
1. 计算查询向量与所有 `nlist` 个质心的距离（代价极小）；
2. 挑出最近的 `nprobe` 个簇（如 nlist=4096，nprobe=32，只看 0.8% 的数据）；
3. 只在这几个簇内做精确（或 PQ 压缩后的近似）距离计算。

```
              ┌───┐        ┌───┐
        ┌─────┤ q ├──┬─────┤   │      ★ 质心
        │     └───┘  │     └───┘      · 数据点
     ┌──▼──┐      ┌──▼──┐
     │  ✓  │      │  ✓  │     nprobe = 2：只搜索 q 最近的两个簇
     │ ··  │      │ ··· │     nprobe 越大 → 召回越高、速度越慢
     └─────┘      └─────┘
```

- **优点**：结构简单、训练快、支持增量；**缺点**：簇边界附近的点可能漏掉（查询点靠近边界时，真近邻可能在"隔壁簇"）；
- 经典组合 **IVF-SQ8 / IVF-PQ**：在簇内再用量化压缩，进一步省内存。

### 5.4 HNSW：分层可导航小世界图（当前最主流）

**HNSW（Hierarchical Navigable Small World，Malkov & Yashunin, 2018）** 是目前业界召回率/速度综合最优、使用最广的索引（Qdrant、Milvus、Weaviate、pgvector 等的默认或主打索引）。思想借鉴**跳表（Skip List）**：把图组织成多层，上层稀疏（长边，快速跨越）、下层稠密（短边，精确定位）。

**建图**：
- 每个向量插入时按指数分布随机分配一个层级：`level = floor(−ln(uniform(0,1)) × mL)`，绝大多数点只在第 0 层，越高层数量指数递减；
- 每个点在第 0 层最多连接 `M` 个近邻（典型 M=16~48），在更高层连接 `M_max = M/2` 个；
- 插入时用下述搜索流程找到各层的最近邻并互相连边，同时维持图的整体连通性。

**查询（贪心 best-first 搜索）**：

```
从最顶层的入口点出发
   │
   ▼  在每一层：贪心移动——检查当前点的邻居，
   │  若有邻居离查询 q 更近就跳过去，直到无法更近（局部最优）
   ▼  该层的最近点作为下一层的入口，逐层下降
   ▼  到第 0 层后：改为维护一个大小为 ef 的候选优先队列，
      持续扩展、收集 ef 个候选
   ▼  取候选中距 q 最近的 K 个返回
```

```
Level 2:   A ──────────── E                 （高层：高速公路，长边跳远）
             ╲            ╱
Level 1:   A ── C ────── E                  （中层）
             ╲   ╲      ╱
Level 0:   A ── C ── D ── E ── F ── G …     （底层：稠密短边，精细搜索）
```

**关键参数**：
- `M`：每点连接数，越大图越稠密、召回越高、内存越大；
- `efConstruction`：建图时候选队列大小，影响图质量（构建更慢）；
- `efSearch`：查询时候选队列大小，**运行时无重建即可调**，直接控制"召回率 ↔ 延迟"的滑杆。

**优点**：高维下召回率极高（>99% 可达）、查询延迟低且稳定、支持增量插入（图是动态的）；**缺点**：内存占用大（存边），删除依赖墓碑标记，构建耗时。

### 5.5 PQ：乘积量化（向量压缩）

**PQ（Product Quantization）** 解决的是另一个维度的问题——**内存**。1 亿条 768 维 float32 向量仅存储就需要约 300GB，全放内存代价高昂。

**压缩算法**：
1. 把 d 维向量**等分为 m 段**（如 768 维 → 96 段 × 8 维）；
2. 对**每一段**独立做 k-means（k=256，刚好 1 字节编码）→ 得到 m 个码本，每个码本 256 个"段质心"；
3. 每条向量用 m 个字节存储——第 i 个字节是"该段与第 i 个码本中最像的质心的编号"。

```
原始向量 [0.12, -0.4, 0.7, ..., 0.33]   768 × 4 字节 = 3072 B
              │  切成 96 段，每段 8 维
              ▼
编码结果  [37, 8, 201, ..., 129]         96 × 1 字节 =  96 B   （32 倍压缩！）
```

**查询（ADC，不对称距离计算）**：查询向量也被切段，预先算出 q 的每段与对应码本 256 个质心的距离表（m×256 次计算）；之后任意向量的近似距离 = 查 96 次表再求和——**把浮点乘加变成查表加法**，既省内存又省算力。代价是量化误差导致召回率下降，实践中与 IVF 组合为 **IVF-PQ**，并在最后用原始向量做精排弥补。

**衍生技术**：
- **OPQ**：先学一个旋转矩阵，使各段方差更均衡，量化失真更小；
- **标量量化 SQ8**：float32 → int8 逐维量化，4 倍压缩、精度损失极小，是最常用的折中；
- **二值量化（Binary Quantization）**：每维 `>0 → 1, ≤0 → 0`，32 倍压缩，配合汉明距离和"重打分"机制可支撑十亿级检索；
- **Matryoshka 嵌入（MRL）**：新一代嵌入模型在训练时就让向量"前缀可用"，检索时先用前 64 维粗筛、再全维精排，实现"套娃式"分级检索。

### 5.6 LSH：局部敏感哈希

**LSH（Locality Sensitive Hashing）** 是概率换速度的经典方案：设计一组**随机超平面哈希函数**，保证"原本相近的向量，以高概率得到相同哈希值"——这与普通哈希（刻意打散）正好相反。

- 每个随机超平面把空间切一半，用"向量落在超平面哪一侧"生成 1 bit，b 个超平面生成 b bit 签名；
- 建 L 张哈希表，查询时在签名匹配的桶内做精确验证；
- 优点：可证明的次线性复杂度、流式友好、理论性质优美；缺点：需要大量哈希表才能保证召回（内存开销大），实际召回/速度均衡不如 HNSW，工业界已较少作为主力索引，但思想广泛用于去重、MinHash 等。

### 5.7 其他重要算法

| 算法 | 出处 | 核心思想 | 特点 |
|------|------|---------|------|
| **Annoy** | Spotify | 随机投影递归切分空间成二叉树森林，多树投票 | 构建慢、查询快、内存映射友好（静态数据） |
| **ScaNN** | Google 2020 | 各向异性量化：损失函数按"查询方向"加权，重点保住与查询平行分量的精度 | CPU 上 recall/吞吐 Pareto 前沿 |
| **DiskANN / Vamana** | 微软 2019 | 图索引 + 量化向量放 SSD，内存只驻留压缩向量做导航，按需读原向量精排 | **单机单 SSD 支撑十亿级**，内存友好 |
| **NSG / NSSG** | 中科大等 | 精心裁剪"单调可达"的近邻图 | 边更少、导航更快，国内多个引擎采用 |
| **NHNSW/GPU 类** | NVIDIA RAFT/CUVS | 图索引构建与搜索 GPU 化 | 十亿级构建从数天缩到数小时 |

### 5.8 算法横向对比

| 索引 | 召回率 | 查询速度 | 内存占用 | 构建速度 | 支持动态增删 | 适用场景 |
|------|--------|---------|---------|---------|-------------|---------|
| Flat | ★★★★★（精确） | ★（慢） | 高 | 无需索引 | 天然支持 | 小数据集、评测基准 |
| IVF-Flat | ★★★☆ | ★★★★ | 中 | 快 | 支持 | 中等规模、需召回可控 |
| HNSW | ★★★★★ | ★★★★★ | **高** | 慢 | 支持 | **通用首选**：低延迟在线服务 |
| HNSW+SQ/BQ | ★★★★ | ★★★★★ | 中 | 慢 | 支持 | 内存敏感的在线服务 |
| IVF-PQ | ★★☆~★★★ | ★★★ | **极低** | 快 | 支持 | 亿级以上、内存极限受限 |
| LSH | ★★ | ★★★ | 高 | 快 | 支持 | 理论场景、流式数据 |
| DiskANN | ★★★★ | ★★★ | **极低**（磁盘） | 中 | 支持 | 十亿级单机、成本敏感 |
| Annoy | ★★★ | ★★★★ | 中 | 慢 | 不支持 | 静态数据、只读场景 |

> 实践中很少"单选"，主流向量数据库普遍采用**组合拳**：分片（IVF 思想）× 图索引（HNSW）× 量化（SQ8/PQ/BQ）× 重排（Flat 精排）。

## 六、一次检索的完整流程

以"在一亿文档中做 RAG 检索"为例：

```
【写入路径】
文档 ──► 切块(chunk, 256~1024 token) ──► Embedding 模型 ──► 向量
        ──► 连同原文、元数据写入向量库 ──► 分片路由 ──► 写 WAL/预写日志
        ──► 进入"成长段"(内存, 暴力可查) ──► 段封存 ──► 后台构建 HNSW/量化索引
        ──► 段合并(Compaction)，删除墓碑回收

【查询路径】
"什么是注意力机制？"
   │ ① 用同一个 Embedding 模型向量化（模型必须与写入时一致！）
   ▼
q = [0.13, -0.42, ..., 0.55]        （768 维）
   │ ② （可选）标量过滤：category = "AI" 且 date > 2024  → 确定可搜索分片
   ▼
   │ ③ ANN 粗排：每个分片用 HNSW 搜出 ef=128 个候选，共约 800 条
   ▼
   │ ④ 精排（Rerank）：用原始向量精确算距离（或 Cross-Encoder 模型重打分），取 Top-50
   ▼
   │ ⑤ 后过滤 + 去重 + 权限校验
   ▼
返回 Top-5 文档块 + 相似度分数 + 原文/元数据
```

三个工程细节值得注意：

- **过滤策略**：标量过滤放在 ANN 前（pre-filter）可能把图索引"切碎"导致导航失败；放在后（post-filter）可能筛完不足 K 条。各库方案不同——Qdrant 用 **Filterable HNSW**（为高频过滤值建侧图），Milvus 在图遍历时实时判断谓词，Weaviate 默认 pre-filter；
- **混合检索（Hybrid Search）**：稠密向量（语义）与稀疏向量（BM25 关键词）各搜一遍，用 **RRF（倒数排名融合）** 或加权融合合并结果——解决"专有名词、型号必须精确匹配"的痛点，是当前 RAG 的标准配置；
- **重排模型**：粗排用双塔向量（快但粗），精排可用 Cross-Encoder（把 query 和 doc 拼一起过 Transformer，慢但准），两段式是精度/延迟的标准权衡。

## 七、工程架构设计

以 Milvus 为代表的云原生向量数据库分层架构（其他产品大同小异）：

```
┌────────────────────────────────────────────────────┐
│ 接入层 Access Layer：SDK/HTTP/gRPC，协议解析、鉴权、路由  │
├────────────────────────────────────────────────────┤
│ 协调器 Coordinator：元数据管理、分片分配、负载均衡、DDL      │
├────────────────────────────────────────────────────┤
│ Worker 节点：                                          │
│   Query Node  —— 加载索引分片，服务读请求                 │
│   Data Node   —— 消费写入日志，落盘到对象存储             │
│   Index Node  —— 异步构建向量索引（CPU/GPU 密集，弹性伸缩） │
├────────────────────────────────────────────────────┤
│ 存储层：对象存储(S3/MinIO, 存快照与索引) + 消息队列(日志序列)  │
│         + etcd(元数据)                                 │
└────────────────────────────────────────────────────┘
```

关键设计：

- **日志即数据（Log as Data）**：写入先顺序追加到分布式日志（如 Pulsar/Kafka），各节点从日志回放状态，写路径简单可靠；
- **段（Segment）机制**：数据按大小切分为段；"成长段"在内存中暴力可查（保证新数据立即可见），写满后封存并异步构建 ANN 索引——用"增量走暴力、存量走索引"解决实时性与索引构建的矛盾；
- **删除与更新**：向量删除用**墓碑标记**（查询时过滤），物理回收依赖段合并（Compaction）；更新 = 删除 + 插入；
- **分片与副本**：按主键哈希把 Collection 分成多个 Shard 并行读写；每个 Shard 维护多个 Replica 提升高可用与读吞吐；
- **缓存与热数据**：HNSW 图、常用段常驻内存；DiskANN 类方案用 SSD + 内存量化导航降成本。

## 八、主流向量数据库对比

| 产品 | 类型 | 索引支持 | 特点 |
|------|------|---------|------|
| **FAISS** | Meta 开源库（C++/Python） | Flat, IVF, HNSW, PQ, GPU 全家桶 | 不是数据库（无分布式/增删管理），但是事实上的算法基础库，很多引擎在其上构建 |
| **Milvus / Zilliz** | 开源分布式 | HNSW, IVF-PQ, DiskANN, GPU-CAGRA 等 | 云原生架构、十亿级验证、功能最全的向量专项数据库 |
| **Qdrant** | 开源（Rust） | HNSW + 量化 | Filterable HNSW、Rust 性能与内存安全、API 设计优雅 |
| **Weaviate** | 开源（Go） | HNSW | 内置向量化模块、GraphQL 接口、原生混合检索 |
| **Pinecone** | 商业 SaaS | 专有（pods/serverless） | 全托管免运维、Serverless 按用量计费 |
| **Chroma** | 开源（Python） | HNSW | 极简 API，AI 应用原型/笔记本场景首选 |
| **pgvector** | PostgreSQL 扩展 | HNSW, IVFFlat | 复用 Postgres 生态与事务、SQL 一把梭，中小规模省一套运维 |
| **Elasticsearch / OpenSearch** | 搜索引擎内置 | HNSW | 与全文检索（BM25）、安全、分析天然一体 |
| **Vespa** | 开源（Yahoo） | HNSW + 多种 | 支持在服务端做张量计算和模型推理（两阶段排序的极致） |
| **Redis** | 缓存内置 | HNSW/FLAT | 微秒级延迟，适合缓存层叠加语义搜索 |

**选型经验法则**：原型/个人项目用 Chroma 或 FAISS；已有 Postgres 且数据量 < 千万级用 pgvector；大规模生产、多租户、复杂过滤用 Milvus/Qdrant/Weaviate；不想运维用 Pinecone/Zilliz Cloud；搜索场景顺手用 Elasticsearch。

## 九、典型应用场景

1. **RAG（检索增强生成）**：文档切块→嵌入→入库；用户提问向量化后召回相关片段，注入 LLM 上下文——缓解大模型幻觉与知识过时，是当前向量数据库最大的驱动力。
2. **语义搜索**：全站商品/文章/代码的"按意思搜"（搜"便宜的保暖外套"能命中"羽绒服促销"）；代码库语义检索（GitHub Copilot 类产品）。
3. **以图搜图 / 以文搜图**：CLIP 类双塔模型的直接应用；电商拍照购、版权图片检测、设计素材检索。
4. **推荐系统**：用户行为序列嵌入、物品内容嵌入双路召回，ANN 检索毫秒级从亿级物品池选千级候选。
5. **音视频处理**：声纹登录（x-vector + 余弦比对）、播客/会议按语义定位（Whisper 向量）、视频去重与版权监测（帧特征指纹）。
6. **数据清洗与安全**：语料去重（近重复向量检测）、异常检测（离群点）、人脸库比对、风控团伙挖掘。
7. **Agent 记忆**：把对话历史嵌入存储，按当前话题召回相关记忆，赋予 LLM 长期记忆能力。

## 十、总结

向量数据库的原理可以浓缩为三句话：

1. **万物皆可嵌入**：神经网络（Transformer、CNN/ViT、3D 网络、语音编码器）把文字、图片、视频、语音统一压缩为稠密向量，训练目标是"语义近 → 空间近"，于是不同模态都可以在同一个几何空间里比较；
2. **高维空间没有便宜的距离计算**：暴力检索 O(N·d) 与维数灾难迫使工程上采用 **ANN 近似最近邻**——以 IVF（聚类分桶）、HNSW（分层图导航）、PQ/SQ（量化压缩）、LSH（概率哈希）为代表，用 1%~5% 的召回损失换取百倍千倍提速，并用"粗排 + 精排重打分"补回精度；
3. **数据库价值在 ANN 之外**：持久化、分布式分片副本、元数据过滤、混合检索（稠密 + 稀疏）、增量更新与实时可见性——这些工程能力才是向量数据库区别于一个 FAISS 脚本的本质。

未来的演进方向包括：**更强的 Embedding 模型**（多模态统一嵌入，如图文音视频共享空间）、**更低成本的索引**（量化算法如 RaBitQ、磁盘索引、GPU 原生索引）、**更智能的检索**（自适应召回、与重排模型联合优化），以及与 LLM/Agent 深度融合的**记忆基础设施**。
