## 一、开始之前：5 个必懂概念 + 3 条保命铁律

### 1.1 概念对照表（用生活类比记）

| 概念 | 类比 | 在你机器上对应什么 |
|---|---|---|
| **Docker Desktop** | 总开关 + 仪表盘 | 任务栏右下角的**鲸鱼图标**；没开它，一切 docker 命令都会报错 |
| **WSL2 虚拟机** | Docker 的"发动机舱"（一个隐形 Linux 小电脑） | 任务管理器里的 `vmmemWSL` 进程；内存上限 8GB（`.wslconfig` 配的） |
| **镜像（image）** | 安装包（只读，一个文件） | `mysql:8.4`、`redis:8.2-alpine` 这些 |
| **容器（container）** | 用安装包装好、**正在运行**的程序实例 | 名叫 `mysql`、`redis`、`kafka` 的三个容器 |
| **卷（volume）** | 外接移动硬盘（程序卸了，数据还在盘上） | `mysql-data`、`redis-data`、`kafka-data` |
| **compose** | "一键装机清单"（yaml 文件写好一批服务） | `D:\code\workspace\docker-stacks\study-stack\compose.yaml` |

一句话串起来：**compose.yaml 是清单 → 清单引用镜像（安装包）→ 跑起来叫容器 → 容器把数据写到卷（移动硬盘）→ 这一切跑在 WSL2 虚拟机里 → Docker Desktop 是这一切的总开关。**

### 1.2 三条保命铁律（新手 99% 的恐慌来自不知道这三条）

1. **数据在卷里，不在容器里。** 只要不带 `-v`，你随便删容器、stop、restart，MySQL 里的数据都安然无恙。
2. **stop ≠ 删除，rm 才是删除，`down -v` 才会连数据一起删。** 看到命令里没有 `rm` 和 `-v`，就放心执行。唯一的高危命令是 `docker compose down -v` 和 `docker system prune --volumes`——本文档会反复提醒。
3. **端口口诀：MySQL=3306、Redis=6379、Kafka=9092。** 这些端口已经映射到本机（`127.0.0.1`），宿主机上的程序（IDEA 里跑的 Spring Boot）直接连 `localhost:3306` 就是容器里的 MySQL。

## 二、首次启动（重启电脑后，只做一次，约 10 分钟）

### 2.1 重启电脑

启用"虚拟机平台"功能后必须重启才生效。**如果你已经重启过，跳到 2.2。**

### 2.2 打开 Docker Desktop 并完成首次设置

1. 开始菜单 → **Docker Desktop** → 启动。
2. 首次启动会弹出 **Docker Subscription Service Agreement**（订阅协议）→ 点 **Accept**。
3. 可能弹出登录/推荐设置页 → 一律 **Skip / 跳过**（不登录也能正常用）。
4. 等待主窗口左下角状态变绿（或托盘鲸鱼图标停止动画），约 1 分钟。

### 2.3 验证引擎活着（第一条命令）

打开 Git Bash（或 PowerShell）：

```bash
docker version
```

**看到什么算成功**：输出分 `Client` 和 `Server` 两段，Server 段有版本号。只有 Client 段、或报 `Cannot connect to the Docker daemon` → Docker Desktop 没开好，回到 2.2 第 4 步等鲸鱼变绿。

再确认 WSL 虚拟机里有它：

```bash
wsl -l -v
```

**看到什么算成功**：列表里有 `docker-desktop`，STATE 是 `Running`。

### 2.4 配置镜像加速（推荐；直连可用时可先跳过）

**实测（2026-10-11）**：这台机器的网络直连 Docker Hub 拉取成功（从 hello-world 到 2.4GB 的镜像全部成功），所以**暂时可以跳过本节**；哪天拉镜像超时了（§7 第 4 条），再回来花 2 分钟配置。配置路径：

1. Docker Desktop 主窗口右上角 ⚙ **Settings** → 左侧 **Docker Engine**；
2. 把编辑框里的 JSON **整体替换**为：

```json
{
  "builder": { "gc": { "enabled": true, "defaultKeepStorage": "20GB" } },
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" },
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run"
  ]
}
```

3. 点 **Apply & Restart**，等鲸鱼重启完（1 分钟左右）。

这段配置干了两件事：`registry-mirrors` 让拉镜像走加速器；`log-opts` 给所有容器日志设 10MB×3 的轮转上限。（实测备注：Docker Desktop 4.94 默认的 `local` 日志驱动已自带 20MB×5 的轮转，所以日志不设上限也不会失控；`registry-mirrors` 才是必配项。）

> 加速器地址是"随时会失效"的公共资源。哪天 pull 超时了（§7 第 4 条），回来换两个新地址即可。更稳的替代：注册**阿里云容器镜像服务个人版**（免费），拿一个人专属的加速地址填进同一个位置。

4. 验证加速生效 + 拉第一个镜像：

```bash
docker run --rm hello-world
```

**看到什么算成功**：输出 `Hello from Docker!`。（这条命令干了什么：从镜像仓库下载一个几 KB 的测试镜像 → 运行 → 自动删除。）

### 2.5 确认"不用时归零"的两个开关

- **Settings → General**：`Start Docker Desktop when you sign in` **不勾**（你大部分时间不用，平时开机零占用，见建议文档 §2.5）；
- **Settings → Resources → Advanced**：`Resource Saver` **开着**（默认开）——以后你开着 Docker 忘了关，5 分钟后它会自动把虚拟机挂起，内存归零。

到这里首次设置完成。**以后每天的使用只有 §3 那几条命令。**

## 三、每天怎么用：启动 / 使用 / 停止学习栈（MySQL + Redis + Kafka）

### 3.0 凭证一览（忘了密码先看这里）

| 服务 | 地址 | 用户名 | 密码 | 说明 |
|---|---|---|---|---|
| MySQL | `localhost:3306` | `root` | 见 `.env` 的 `MYSQL_ROOT_PASSWORD` | `study` 库已自动创建；密码为部署时随机生成 |
| Redis | `localhost:6379` | （无用户名） | 见 `.env` 的 `REDIS_PASSWORD` | Redis 只有密码没有用户名 |
| Kafka | `localhost:9092` | — | — | PLAINTEXT 无认证；安全靠端口只绑 127.0.0.1 |

- **密码存放地**：`D:\code\workspace\docker-stacks\study-stack\.env`（不进 git）。随时查看：`cat` 该文件，或 `docker exec mysql env | grep MYSQL`。
- **改密码**：Redis——改 `.env` 后 `docker compose up -d` 即生效；MySQL——`MYSQL_ROOT_PASSWORD` 只在首次初始化生效，之后要用 `ALTER USER 'root'@'%' IDENTIFIED BY '新密码';` 改，**且必须同步改 `.env`**（compose 健康检查用它，不一致会导致永远 unhealthy）。

### 3.1 启动学习栈

**一键启动**（自动打开 Docker Desktop、等引擎就绪、拉起栈并显示状态，实测冷启动约 1 分钟内全 healthy；源码见附录 B.2，**也可直接双击同目录的 `startup-all.cmd`**）：

```bash
bash /d/code/workspace/docker-stacks/startup-all.sh
```

下面的手工命令是一键脚本的分解动作：

```bash
cd /d/code/workspace/docker-stacks/study-stack
docker compose up -d
```

（干什么：按 compose.yaml 把 MySQL、Redis、Kafka 三个容器全部后台启动。`-d` = 后台运行。）

**第一次启动**会自动下载三个镜像，共约 1.5~2GB，走加速器大约几分钟，请耐心等进度条走完——只发生这一次，以后秒起。

启动后看状态：

```bash
docker compose ps
```

**看到什么算成功**：三个服务 STATUS 都是 `Up xx seconds (healthy)`。

> 注意：MySQL/Kafka 启动后要自检 30 秒左右，STATUS 会先显示 `(health: starting)`，**等到出现 `(healthy)` 才算真就绪**——这是自动健康检查在工作，不是卡住。

### 3.2 连接测试（不需要在 Windows 上装任何客户端）

**Redis**：

```bash
docker exec redis redis-cli -a "ffb4c9be878cde5c0af6b7b3" ping
```

**看到什么算成功**：`PONG`。（干什么：进入 redis 容器内部执行 redis-cli；密码来自同目录 `.env` 文件。）

**MySQL**：

```bash
docker exec mysql mysql -uroot -p"7c0e0059c35a9391232befb0" -e "SELECT VERSION(); USE study; SELECT * FROM demo_user;"
```

**看到什么算成功**：版本号 `8.4.x`、数据库列表里有 `study`、demo_user 表里有 alice 和 bob 两行（首次初始化脚本自动建的）。会提示一行 `Using a password on the command line interface can be insecure` 警告——无害，学习环境忽略。

**Kafka**（建一个测试主题、收发一条消息；注意命令里是 `//opt` 双斜杠——这是规避 Git Bash 的路径转换：以 `/` 开头的参数会被改写成 Windows 路径。你用 PowerShell 的话单斜杠也对，双斜杠同样正确）：

```bash
# 建主题
docker exec kafka //opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic demo --partitions 1 --replication-factor 1
# 看主题列表
docker exec kafka //opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
# 发消息（进入交互模式，敲一行回车一条，Ctrl+C 退出）
docker exec -it kafka //opt/kafka/bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic demo
# 收消息
docker exec kafka //opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic demo --from-beginning
```

### 3.3 日常观察三连

```bash
docker compose logs -f mysql        # 追着看某个服务的实时日志（Ctrl+C 退出）
docker stats                        # 所有容器的实时 CPU/内存占用（Ctrl+C 退出）
docker exec -it mysql bash          # 钻进 mysql 容器内部（像登录一台 Linux；exit 退出）
```

### 3.4 停止（三种"停法"，按需选）

**一键归零**（推荐；等价于下面"停法三"的全部分解动作，最后自动逐项验证，实测三项验证全 OK；源码见附录 B.1，**也可直接双击同目录的 `shutdown-all.cmd`**）：

```bash
bash /d/code/workspace/docker-stacks/shutdown-all.sh
```

```bash
# 停法一：今天不用了（容器停、数据全留）——日常推荐
docker compose stop

# 停法二：连容器定义一起删（数据仍在卷里，up -d 秒级重建回来）
docker compose down

# 停法三：彻底归零的四个分解动作（手工操作时照此顺序）：
#   ① 停容器：cd 到栈目录，docker compose stop（Docker 没开着就跳过这步）
#   ② 查残留：docker ps —— 应该为空
#   ③ 退 Desktop：托盘鲸鱼图标右键 → Quit Docker Desktop
#   ④ 关虚拟机：wsl --shutdown（无损，下次打开 Docker Desktop 自动重建）
```

**停完怎么确认真的归零了**（三条都符合即成功）：

- 任务管理器搜 `vmmemWSL` 和 `Docker Desktop` —— 都搜不到；
- `wsl -l -v` —— `docker-desktop` 显示 Stopped（或提示无运行中的发行版）；
- `docker ps` —— 报 `Cannot connect to the Docker daemon`（引擎已关，这是正常的）。

**何时用哪个**：每天用完 → 停法一；想清清爽爽过周末/关机前 → 停法三（或一键脚本）；停法二介于中间，很少需要。

> ⚠️ **全手册唯一的危险命令**：`docker compose down -v`——`-v` 连卷（移动硬盘）一起删，MySQL 数据全没。只在"我想把学习环境彻底重置"时用，用之前先跑一次 §5 的备份。

## 四、部署你自己的 Spring Boot 应用

### 4.1 第一步：确认 Boot 版本，写 Dockerfile 与 .dockerignore

先打开项目 `pom.xml`，看 `<parent>` 里 `spring-boot-starter-parent` 的版本：**≥3.3（含 4.x）用模板 A；≤3.2 用本节末尾的模板 B**。两个文件都放**项目根目录**。

**`Dockerfile`（模板 A，Boot 3.3+ / 4.x 官方写法，含分层、非 root、优雅停机）**：

```dockerfile
# ---- 阶段一：把 fat jar 解压成"依赖层 + 代码层" ----
FROM eclipse-temurin:25-jre AS builder
WORKDIR /builder
# Maven 项目是 target/*.jar；Gradle 改成 build/libs/*.jar
ARG JAR_FILE=target/*.jar
COPY ${JAR_FILE} application.jar
RUN java -Djarmode=tools -jar application.jar extract --layers --destination extracted

# ---- 阶段二：运行镜像 ----
FROM eclipse-temurin:25-jre
RUN useradd --system --create-home app
USER app                                # 非 root 运行
WORKDIR /application
# 四个 COPY 各成一层：依赖在前、代码在后——改代码只重建最后一层
COPY --from=builder /builder/extracted/dependencies/ ./
COPY --from=builder /builder/extracted/spring-boot-loader/ ./
COPY --from=builder /builder/extracted/snapshot-dependencies/ ./
COPY --from=builder /builder/extracted/application/ ./
ENV TZ=Asia/Shanghai \
    JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75.0 -XX:+ExitOnOutOfMemoryError -Dfile.encoding=UTF-8"
# exec 形式（JSON 数组）：docker stop 时 SIGTERM 直达 java，优雅停机的前提
ENTRYPOINT ["java", "-jar", "application.jar"]
```

**`.dockerignore`**（防止把无关文件塞进构建上下文）：

```
.git
.idea/
*.iml
HELP.md
logs/
target/classes/
target/test-classes/
target/maven-status/
.env
```

两个设计意图：**多阶段**让最终镜像只含 JRE 和应用（无源码、无 Maven）；**分层 COPY** 让"改一行代码"只重建最后的代码层、依赖层直接命中缓存。基础镜像 `eclipse-temurin:25-jre` 已在本机（见 §九），首次构建不需要联网下载。Dockerfile **逐行对照表**见样例工程 `D:\code\workspace\hello-world\README.md` §4.1。

> 为什么模板里**没有** `# syntax=docker/dockerfile:1`：官方示例首行有它，但这会让 BuildKit **每次构建都去 Docker Hub 拉 frontend 镜像**，国内网络经常在这一步超时；本模板没用到它支持的高级语法，删掉即可（实测：删掉后配合本地基础镜像可**完全离线构建**）。

**模板 B（仅 Boot ≤3.2 用）**：解压命令换成 `java -Djarmode=layertools -jar application.jar extract`（无 `--destination`，产出目录为 `/builder/application/`），四个 COPY 路径相应改为 `/builder/application/dependencies/` 等，ENTRYPOINT 换成 `["java", "org.springframework.boot.loader.JarLauncher"]`。**多模块项目**把 `ARG JAR_FILE` 指到对应模块：`ARG JAR_FILE=模块名/target/*.jar`。

### 4.2 构建并运行（第一次）

> 现成样例：`D:\code\workspace\hello-world` 是按本节搭好的 Spring Boot 4.1.1 实战工程（已构建 `hello-world:dev` 并验证 HTTP 访问），可直接对照；工程内 `README.md` 就是"开发→Dockerfile→打包→部署"的全流程文档，**新项目可直接以它为模板**。

```bash
cd /d/code/workspace/你的项目
mvn -q package -DskipTests                          # ① 宿主机打包出 target/*.jar
docker build -t demo:dev .                          # ② 把 jar 做成镜像（分层缓存，第一次慢以后快）
docker run -d --name demo -p 127.0.0.1:8080:8080 demo:dev   # ③ 后台运行：容器名叫 demo，8080 映射到本机
docker logs -f demo                                 # ④ 看启动日志（看到 Started ... in x seconds 即成功）
curl http://localhost:8080/actuator/health          # ⑤ 验证（返回 {"status":"UP"...}）
```

（命令口诀：**build 是"打包成安装包"，run 是"安装并启动"，`-d` 是后台，`-p` 是端口映射 `本机:容器`，`--name` 给它起个名字**。）

### 4.3 改了代码之后（每天的循环，就这四行）

```bash
mvn -q package -DskipTests
docker rm -f demo                    # 删掉旧容器（数据型应用别这么干，应用无状态没关系）
docker build -t demo:dev .
docker run -d --name demo -p 127.0.0.1:8080:8080 demo:dev
```

> 建议文档 §1.3 说过的定位：这是**外循环**（阶段性验证）。日常改一行试一下，还是 IDEA 里直接 Run 最快。

### 4.4 让应用连上学习栈

关键认知：**容器里的 `localhost` 是容器自己**，不是 Windows。按"应用在哪跑"决定地址（完整拓扑表见建议文档 §4.2）：

- 应用跑宿主机（IDEA）→ 连 `localhost:3306 / 6379 / 9092`，密码用 `.env` 里的值；
- 应用跑容器里 → 地址用 `host.docker.internal`（Docker 提供的特殊域名，指向宿主机）。

推荐把地址写成环境变量、默认 localhost——**IDEA 和容器两种跑法代码零改动**：

```yaml
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:3306/study?serverTimezone=Asia/Shanghai
    username: root
    password: ${DB_PASSWORD:7c0e0059c35a9391232befb0}
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      password: ${REDIS_PASSWORD:ffb4c9be878cde5c0af6b7b3}
```

容器启动时注入两个变量：

```bash
docker run -d --name demo -p 127.0.0.1:8080:8080 \
  -e DB_HOST=host.docker.internal \
  -e REDIS_HOST=host.docker.internal \
  demo:dev
```

> Kafka 注意：study-stack 已配**双 listener**（2026-10-11 起）：宿主机应用连 `localhost:9092`；**容器里的应用 bootstrap 必须用 `host.docker.internal:29092`**——Kafka 客户端按 bootstrap 端口匹配广播地址，用 9092 会选中 `localhost:9092` 然后在容器内连自己（报 `Connection to node (localhost/127.0.0.1:9092)`）。原理见 `D:\ai\mq` Kafka 笔记的 listener 机制；三组件串联的实战样例见 `D:\code\workspace\hello-component`（含 Boot 4 需显式引入 `spring-boot-kafka` 模块的坑）。

### 4.5 应用不用了

```bash
docker stop demo && docker rm demo   # 停止并删除（无状态应用随便删，镜像还在）
```

## 五、数据备份与还原（改库之前 / 每月一次）

脚本已放在 `D:\code\workspace\docker-stacks\backup.sh`（打包三个数据卷 + mysqldump 全库导出，产物落 `D:\code\backup`；源码见附录 B.3，也可直接双击同目录的 `backup.cmd`）。


## 六、磁盘清理（每月一次，或 D 盘/C 盘告警时）

```bash
docker system df            # ① 体检：镜像/容器/卷/构建缓存各占多少
docker system prune         # ② 清理：停止的容器、悬空镜像、无用网络（不删卷、不删在用镜像）
docker builder prune        # ③ 构建缓存单独清（常是隐形大头）
docker volume prune         # ④ 只清理"没有任何容器引用"的卷（仍会问你确认）
```

> ⚠️ 红线：`docker system prune -a --volumes` 是"能删的都删"，会删掉你没在跑的镜像**和**数据卷——除非你明确要重置，否则不要加 `-a` 和 `--volumes`。

镜像和卷删掉之后，Windows 里的虚拟磁盘文件（vhdx）不会自动变小。做一次彻底收缩：

```powershell
# PowerShell（普通权限即可）
wsl --shutdown
# 已开启 sparseVhd（.wslconfig 里配了），系统会逐步自动回收；若仍偏大，管理员 PowerShell 执行：
# wsl --manage docker-desktop --set-sparse true
```

## 七、报错速诊（症状 → 原因 → 一招解决）

| 症状（报错关键词） | 原因 | 解决 |
|---|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop 没开/没就绪 | 打开它，等托盘鲸鱼变绿再执行命令 |
| `Bind for 0.0.0.0:3306 failed: port is already allocated`（或 Windows 提示端口被占用） | 3306/6379/9092 被本机其他程序占了 | `netstat -ano | findstr 3306` 找到占用者关掉；或改 compose.yaml 里 `127.0.0.1:` 后面的宿主机端口 |
| `docker compose up` 提示 `environment variable ... is not set` | 没在 study-stack 目录里执行，或 `.env` 不在 | `cd` 到 stack 目录；确认 `.env` 文件存在 |
| pull 长时间无进度 / `i/o timeout` / `TLS handshake timeout` | 镜像加速器失效（常态） | §2.4 的 JSON 里换两个新加速地址，Apply & Restart 重试 |
| 容器秒退，`docker ps -a` 里 `Exited (137)` | 内存超限被系统强杀（OOM） | `docker inspect mysql --format '{{.State.OOMKilled}}'` 确认；调大 compose.yaml 里 `mem_limit` 或调小应用堆（建议文档 §6.1） |
| `The container name "/mysql" is already in use` | 同名旧容器还在 | `docker rm mysql`（或 `docker rm -f mysql` 强制）再启动 |
| `no space left on device` | 磁盘满 | §6 清理三连 + vhdx 收缩 |
| 休眠唤醒后命令卡住/容器网络不通 | WSL 时钟漂移/网络栈卡住 | `wsl --shutdown`，重开 Docker Desktop |
| 宿主机程序连 `localhost:3306` 被拒绝 | 栈没启动，或 MySQL 还没 `(healthy)` | `docker compose ps` 看状态，等到 healthy |
| 容器里时间差 8 小时 | 默认 UTC | compose 里已配 `TZ: Asia/Shanghai`；自己的新服务记得也配 |
| 挂进容器的脚本报 `\r: command not found` | Windows 换行符 CRLF | 项目加 `.gitattributes`：`*.sh text eol=lf`，重新 checkout |
| `docker build` 报 `COPY failed ... no source files` | 忘了先 `mvn package`，jar 不存在 | 先 `mvn -q package -DskipTests`；多模块项目把 `ARG JAR_FILE` 指到 `模块名/target/*.jar`（§4.1） |
| 容器里的应用连不上数据库（IDEA 里能连） | 容器里的 localhost 是容器自己 | 启动时注入 `-e DB_HOST=host.docker.internal`（§4.4） |
| `docker build` 卡在 `resolve image config for docker.io/docker/dockerfile:1` 后超时 | `# syntax=` 指令强制联网拉 frontend 镜像 | 删掉 Dockerfile 首行 `# syntax=`（手册模板已删）；或配加速器 |
| 容器里的 Kafka 应用报 `Connection to node (localhost/127.0.0.1:9092)` | bootstrap 端口匹配选中了宿主机侧 listener | bootstrap 改用 `host.docker.internal:29092`（双 listener 的容器侧端口，§4.4） |
| Boot 4 应用启动报 `required a bean of type 'KafkaTemplate' that could not be found` | Boot 4 把 Kafka 自动配置挪进了独立模块 | pom 加依赖 `org.springframework.boot:spring-boot-kafka` |
| curl 中文参数返回 400（应用日志里 Tomcat 解码异常） | Git Bash 控制台按 GBK 把中文传给 curl，Tomcat 按 UTF-8 解码失败 | 测试参数用 ASCII；或把内容写进 UTF-8 文件用 `--data-urlencode content@file.txt`；或用浏览器 |
| Kafka 容器重建后 topic/消息全丢 | apache/kafka 官方镜像默认 log.dirs 在 `/tmp`（易失），挂载卷没被用上 | compose 加 `KAFKA_LOG_DIRS: /var/lib/kafka/data`（study-stack 已修，2026-10-11） |

### B.1 shutdown-all.sh（一键归零：停容器 → 退 Desktop → 关 WSL → 逐项验证）

```bash
#!/usr/bin/env bash
# 归零脚本：停容器 → 退 Docker Desktop → 关 WSL 虚拟机 → 逐项验证
# 用法（Git Bash）：  bash /d/code/workspace/docker-stacks/shutdown-all.sh
# 数据全部保留在卷里；下次要用跑 startup-all.sh 一键回来。
STACKS_DIR=/d/code/workspace/docker-stacks

if docker version --format '{{.Server.Version}}' >/dev/null 2>&1; then
  echo "== 1/4 停止所有 compose 栈 =="
  found=0
  for d in "$STACKS_DIR"/*/; do
    if [ -f "$d/compose.yaml" ]; then
      found=1
      echo "-- $(basename "$d")"
      (cd "$d" && docker compose stop 2>&1 | sed 's/^/   /')
    fi
  done
  [ "$found" = 0 ] && echo "(栈目录里没有 compose.yaml，跳过)"

  echo "== 2/4 检查残留容器 =="
  left=$(docker ps -q 2>/dev/null)
  if [ -n "$left" ]; then
    echo "仍有容器在跑："
    docker ps --format "   {{.Names}} ({{.Status}})"
    echo "   如需强制停止：docker stop \$(docker ps -q)"
  else
    echo "(无运行中的容器)"
  fi
else
  echo "== 1/4、2/4 跳过：Docker 引擎本来就没在运行 =="
fi

echo "== 3/4 退出 Docker Desktop + 关闭 WSL 虚拟机 =="
if powershell.exe -NoProfile -Command 'if (Get-Process "Docker Desktop" -ErrorAction SilentlyContinue) { exit 0 } else { exit 1 }'; then
  powershell.exe -NoProfile -Command 'Get-Process "Docker Desktop","com.docker.backend","com.docker.build" -ErrorAction SilentlyContinue | Stop-Process -Force'
  echo "Docker Desktop 已退出"
else
  echo "Docker Desktop 本来就没在运行"
fi
if wsl.exe --shutdown 2>/dev/null; then
  echo "WSL 虚拟机已关闭"
else
  echo "WSL 关闭命令未生效（通常本就没在运行，可忽略）"
fi
sleep 2

echo "== 4/4 逐项验证 =="
if powershell.exe -NoProfile -Command 'if (Get-Process vmmemWSL -ErrorAction SilentlyContinue) { exit 1 } else { exit 0 }'; then
  echo "[OK] vmmemWSL 已消失（内存已释放）"
else
  echo "[!!] vmmemWSL 仍在运行（内存未释放）"
fi
if powershell.exe -NoProfile -Command 'if (Get-Process "Docker Desktop" -ErrorAction SilentlyContinue) { exit 1 } else { exit 0 }'; then
  echo "[OK] Docker Desktop 已退出"
else
  echo "[!!] Docker Desktop 仍在运行"
fi
wsllist=$(wsl.exe -l -v 2>/dev/null | iconv -f UTF-16LE -t UTF-8 2>/dev/null)
if echo "$wsllist" | grep -q "Running"; then
  echo "[!!] 仍有 WSL 发行版在运行："
  echo "$wsllist" | sed 's/^/     /'
else
  echo "[OK] 无运行中的 WSL 发行版"
fi
echo "归零完成。数据都在卷里，下次 startup-all.sh 一键回来。"
```

### B.2 startup-all.sh（一键启动：开 Desktop → 等引擎 → 启动所有栈 → 显示状态）

```bash
#!/usr/bin/env bash
# 一键启动：打开 Docker Desktop → 等引擎就绪 → 启动所有栈 → 显示状态
# 用法（Git Bash）：  bash /d/code/workspace/docker-stacks/startup-all.sh
STACKS_DIR=/d/code/workspace/docker-stacks

echo "== 1/3 启动 Docker Desktop =="
if docker version --format '{{.Server.Version}}' >/dev/null 2>&1; then
  echo "引擎已在运行"
else
  powershell.exe -NoProfile -Command 'Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"'
  printf "等待引擎就绪"
  up=0
  for i in $(seq 1 36); do
    sleep 5
    if docker version --format '{{.Server.Version}}' >/dev/null 2>&1; then
      up=1; echo " -> 就绪（约 $((i*5)) 秒）"
      break
    fi
    printf "."
  done
  if [ "$up" = 0 ]; then
    echo ""
    echo "[!!] 引擎 180 秒内未就绪——打开 Docker Desktop 窗口看有没有报错，处理后重跑本脚本"
    exit 1
  fi
fi

echo "== 2/3 启动所有 compose 栈 =="
for d in "$STACKS_DIR"/*/; do
  if [ -f "$d/compose.yaml" ]; then
    echo "-- $(basename "$d")"
    (cd "$d" && docker compose up -d 2>&1 | sed 's/^/   /')
  fi
done

echo "== 3/3 当前状态（MySQL/Kafka 要 ~30 秒才到 (healthy)，属正常） =="
sleep 3
for d in "$STACKS_DIR"/*/; do
  if [ -f "$d/compose.yaml" ]; then
    (cd "$d" && docker compose ps --format "  {{.Name}}: {{.Status}}")
  fi
done
echo "完成。"
```

### B.3 backup.sh（数据备份：打包三个数据卷 + mysqldump 全库导出）

```bash
#!/usr/bin/env bash
# 备份学习栈数据 —— 用 Git Bash 执行：bash /d/code/workspace/docker-stacks/backup.sh
# 物理备份（打包数据卷）+ 逻辑备份（mysqldump），产物落到 D:\code\backup

echo "备份完成 -> $DEST"
ls -lh "$DEST" | tail -5
```

### B.4 怎么执行 .sh 脚本？（cmd 直接跑不了是正常的）

`.sh` 是 bash 语法的脚本，cmd / PowerShell 都不认识。三种方式任选：

| 方式 | 操作 | 适合 |
|---|---|---|
| ① 双击 .cmd 包装器（最省事） | 资源管理器进入 `D:\code\workspace\docker-stacks\`，双击 `startup-all.cmd` / `shutdown-all.cmd` / `backup.cmd` | 日常使用 |
| ② Git Bash 窗口 | 开始菜单搜 `Git Bash`（或文件夹空白处右键 `Open Git Bash here`）→ `bash /d/code/workspace/docker-stacks/shutdown-all.sh` | 想顺带敲其他命令 |
| ③ cmd / PowerShell 里调 bash | `bash D:/code/workspace/docker-stacks/shutdown-all.sh`（`bash` 已在 PATH 且指向 Git 的 bash，与 WSL 不冲突） | 已经开着 cmd 不想切换 |

双击版包装器源码（三个文件只有脚本名不同；`chcp 65001` 让窗口按 UTF-8 正确显示中文输出，`pause` 让执行完窗口停住、好看到 `[OK]` 验证结果）：

```bat
@echo off
rem Double-click wrapper: run shutdown-all.sh via Git Bash (chcp 65001 = UTF-8 output)
chcp 65001 >nul
"C:\Program Files\Git\bin\bash.exe" /d/code/workspace/docker-stacks/shutdown-all.sh
pause
```

安装过程中的临时日志在 `D:\tmp\`（vmp.log、wsl-winget.log、docker-winget.log），可随时清理。
